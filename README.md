- 手填输入另设原始输入组；对应计算和温度边界判断另列，不覆盖设备实测或设备告警。仅使用齐全且有效的必要输入，缺失不补零。速率/顺序峰值不是饱和度，主机写入/TBW 不是磨损或寿命百分比。

## 严格分类与悬浮窗逐项选择

主界面和半隐藏悬浮窗现在共用 `MetricCatalog.cs` 指标目录，分类、名称、取值和缺失说明保持一致。

- **原始数据**：本软件从系统/硬盘直接获取的值，包括系统返回的 MB/s、IOPS、空闲占比、设备报告状态、磨损、温度、错误等。系统或厂家内部是否计算过，不改变它们对本软件而言是原始输入的事实。单位换算和脱敏属于展示，不另立计算指标。
- **计算指标**：本软件计算的忙碌占比、总吞吐、写入占比、平均请求大小、温度/备用空间余量、基线中位数/MAD/P95、z 分数、样本计数等可复算数值。
- **结论**：本软件按规则作出的健康、温度、近期写入状态，以及性能瓶颈/长期趋势的证据不足结论。是否是数值不是唯一标准：风险等级即使用数字编码，仍是判断结论。
- **附加功能**：Ping0 节点风控、IP、位置、ASN 等网络信息独立于磁盘数据。文件探针作为独立主动测试工具显示，不将一份全局测试结果冒充每块硬盘的结果。

显示设置中的四类折叠列表支持逐项勾选；原来捆绑的累计读取/写入、读/写错误、温度/上限等现在分别选择。选择保存在现有配置文件中，旧配置按原开关迁移默认值。新增的指标默认不勾选，网络查询与探针的启用仍由原功能开关控制，勾选显示不会发送网络请求或执行测试。

悬浮窗右上角“指标”打开选择设置；按磁盘分组，内部按三类展示，只出现已选指标。可折叠类别，采样刷新不会重置折叠状态；未采集或过期的数据保留灰色提示。默认窗口 380×460，可缩放和滚动。完整界面的原始/计算页不再混入本软件健康状态徽章；状态判定留在结论页。公式和判断依据通过悬停提示查看，原有说明流程图保留。

## 客观评价：实测、设备阈值与历史参照

“计算指标”和“结论”新增独立状态卡：实测工作负载、忙碌占比、平均请求大小、性能瓶颈、近期写入偏移、设备温度余量、健康证据、长期变化与字段可用性。保留原有可视化流程图，评估依据页面增加公式和适用边界。

- 忙碌占比使用 `100 − PhysicalDisk/% Idle Time`，不是带宽利用率；总览是各盘算术均值。无效计数器明确显示无法获取，不补成零；曲线在缺失时清空，避免跨缺口连接或计算频谱。
- 吞吐量 = 读取速率 + 写入速率；写入占比 = 写入 / 总吞吐；平均请求大小约为总吞吐 / IOPS。组合计数器是近似同区间估计，不能识别随机/顺序模式。没有完成请求时不适用。
- 温度仅与设备报告上限比较，删除“摄氏温度达到上限 90%”的经验预警。缺阈值时只记录温度；协议温度告警独立有效。
- 磨损 100% 仅提示估计耐久度已消耗，不宣称已经故障；取消统一 90% 磨损警戒。历史不可纠正错误提示关注，但没有差分快照时不宣称当前正在发生错误。
- 已采集且可判定的字段无告警时显示“未见告警”，不保证整盘健康。只有温度/磨损值而没有足够健康判据时保持未知。
- 区间延迟和同类负载参照尚未采集，性能瓶颈保持无法判定。历史学习仍仅在内存，长期性能/磨损趋势显示样本不足，不提供剩余寿命或故障概率。
- 多维评价的新鲜度窗口：性能 max(5秒, 3倍采样周期)，健康 max(60秒, 2倍健康周期)。字段覆盖数量不是统计置信度。这些是软件数据有效性规则，不是厂家风险阈值。

字段依据：[微软存储可靠性计数器](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/msft-storagereliabilitycounter)、[NVMe 健康日志与 PercentageUsed 语义](https://learn.microsoft.com/en-us/windows/win32/api/nvme/ns-nvme-nvme_health_info_log)。

启动与白屏兼容更新：默认使用 WPF 软件合成，避开部分显卡/远程显示环境的硬件合成兼容问题；软件绘制可能增加前台 CPU 开销，后台仍暂停隐藏界面的绘图。仅在排查问题时可用 `--hardware-rendering` 对比硬件渲染。加入单实例控制，再次双击启动会恢复已有窗口。日常只使用项目目录中的 `DiskGuard-Desktop.exe`，不再保留带版本号的多份启动文件；便携 ZIP 始终装入同一版 EXE。

节点风控与布局更新：全展示和悬浮窗增加独立风控分值与风险条，验证 `iprisk` 为 0–100 的有限数值，并核对接口返回 IP 与请求目标一致。免费地址、`/geo` 及 JSONP 接口均不提供风控值；详细接口需要用户自行申请付费 Key，程序不会代购或绕过付费接口。查询出口是本程序的网络出口，未必等同于其他应用使用的代理节点。官方说明：[API](https://ping0.cc/ip/api)、[风控分档 FAQ](https://ping0.cc/ip/faq)。本程序按上界包含分档：≤15 极度纯净、≤25 纯净、≤40 中性、≤50 轻微风险、≤70 稍高风险、>70 极度风险；这是服务方参考评分，不是事故概率。

颜色分为两个用途：曲线、图例和指标标题前色点使用相同系列映射（读取蓝、写入青、IOPS 紫、队列品红、活跃蓝灰），只用于识别指标；普通数值保持中性。绿/橙/红的状态数值才表示明确正常/关注/严重，灰色表示未采集或未判断。网络请求成功不代表节点安全。卡片恢复内边距，长型号和标题换行，图例与设置行适应宽度；指标在宽屏最多六列，窄窗口或大字号自动减少列数。

文字清晰度更新：正文和说明默认至少 13 DIP，指标数值默认 14 DIP；显示设置 → 字体与层级新增“标准 · 清晰 / 较大 / 大号”，可保存文字大小并同步到悬浮窗。启用 Display 文字排版、布局取整及像素对齐；中文明确回退到微软雅黑，避免选择英文字体后中文风格不一致。提高浅色模式说明、正常值及警示值的对比度，文字承载卡片改为不透明底色，移除卡片和悬浮窗的整层阴影效果。主界面使用 ClearType，透明窗口使用灰度抗锯齿，悬浮窗默认不降低整体透明度。不同屏幕、系统缩放和字体设置下的观感仍需实机确认。

2026-09-15 更新：探针按物理硬盘显示独立路径行，支持“浏览…”点选文件夹和逐盘勾选；设置按设备身份保存。多块硬盘依次测试，执行前重新核对盘符归属；无盘符、目录联接、网络路径和无法唯一映射的卷不执行测试。插拔硬盘后可点“刷新硬盘”。旧版单路径仅迁移路径，不自动勾选硬盘。文件大小和计划是各勾选硬盘共享的设置。

关闭右上角 × 会隐藏主窗口和悬浮窗，继续后台监测；系统托盘图标可双击恢复，右键打开主界面、显示悬浮窗或退出。真正退出请用“退出程序”，运行中的探针需先完成清理。隐藏或最小化主窗口时停止主界面的图表计算和重建，悬浮窗隐藏时停止其刷新；采样及用户已启用的计划任务仍然运行。WPF 默认使用硬件加速，前台可能使用 GPU；后台停止绘制不等于承诺显存释放或 GPU 占用绝对为零。

探针时间上限现在覆盖写入及读回循环，但同步 I/O 和 Flush 正在执行时无法保证立即中断。探针仍受缓存、并发进程和系统环境影响，不用于推算剩余寿命。

直接运行 DiskGuard-Desktop.exe。使用 Windows .NET Framework 4.x 自带的 WPF 组件，无需 Python、安装程序或后台服务；默认不联网，只有在设置中主动启用 Ping0 节点查询后才会发起网络请求。

当前界面包含总览、详细指标、显示设置和评估依据。详细指标页按“原始数据 → 计算指标 → 结论”分层，可按硬盘下拉筛选；性能图可勾选读取、写入、IOPS、队列、活跃度，并在时域趋势与频率谱之间切换。时域使用平滑曲线，频域使用去均值 + Hann 窗的一侧 DFT 柱状谱；多指标叠加时逐条独立归一化并明确标注。设备字段使用每行 6 项的高密度静态栅格、数值与进度条，结论使用分级证据卡。评估依据页用流程图、分类树和公式卡说明“采集 → 分类 → 计算 → 筛选 → 结论”。悬浮插件是独立窗口，置顶、可拖动、可调透明度；切换主页面、最小化主窗口都不会让它消失。显示设置可控制实时性能、健康、温度、磨损、错误、通电时间和 NVMe 累计读写量，并保存在本机的小型配置文件中；主题支持跟随系统、浅色和深色，字体支持 Microsoft YaHei UI、Segoe UI、Microsoft JhengHei UI，所有控件统一继承所选字体。

实时吞吐、IOPS、队列长度和活跃度通过 Windows PhysicalDisk 性能计数器读取，界面以 MB/s、GB、TB 等十进制单位显示；健康信息尽力读取 Win32_DiskDrive、MSFT_PhysicalDisk、MSFT_StorageReliabilityCounter 和 SMART 预测状态。NVMe 设备还会通过 Windows 10+ 的只读 IOCTL_STORAGE_QUERY_PROPERTY 查询 Identify 与 SMART/Health 日志，补充温度、寿命百分比、备用空间、读写数据量、通电时间、异常关机、介质错误和错误日志等字段。不同主板、USB 桥接、RAID 或控制器可能不暴露温度、磨损或错误字段，缺失时显示“未采集”并显示数据来源/接口状态。

采集频率可以在“显示设置”中分别调整：性能计数器为 1 / 2 / 5 / 10 秒，健康、温度、SMART/可靠性字段为 1 / 5 / 15 / 30 分钟。健康字段启动时读取，运行期间仅在检测到磁盘活动且到达设定间隔时轮询，空闲时不会为了采样频繁唤醒机械硬盘；“详细指标”页提供“立即刷新健康数据”按钮。

节点纯净度参考（Ping0）是独立的可选网络模块，不参与硬盘寿命评分。开启后，软件可通过 `https://ping0.cc/geo` 读取当前公网 IP、位置、ASN 和组织；若填写 API Key，则按 Ping0 的 `apiloc/apikey(...)/ip(...)` 接口读取 `iprisk`、是否机房节点、是否原生 IP、ASN 类型等字段。API Key 只保存在本次运行的内存中，不写入配置文件；公网 IP 默认在界面中遮罩显示。自动更新默认 30 分钟，可选 15 / 30 / 60 分钟，并可手动检测。详细接口由 Ping0 官方说明为 0.1 元/次且 1 万次起购，因此程序不会在未启用时访问，按官网公开分档解释 Ping0 原始风险值；这些标签不作为本程序的安全保证。查询只涉及 IP / 节点信息，不上传硬盘型号、读写数据或文件内容。

数据角色严格分开：设备自报的 SMART / Health、磨损、备用空间、介质错误和不可纠正错误属于“寿命证据”；当前读写、IOPS、队列、活跃度和当前温度属于“瞬时运行风险”；通电小时、累计读写量、异常关机、控制器忙时间等属于“累计暴露背景”。瞬时负载不会被当成寿命下降，累计暴露也不会单独制造寿命结论；温度只与设备报告的上限比较，不使用跨硬盘的绝对阈值。当前 WPF 版的学习样本是同一硬盘的内存环形历史，重启后会重新暖机，不会把不同硬盘或不同日期的工作量混成一个“寿命基准”。

学习样本的规则在“评估依据”页按章节和流程图展示：写入速度先做 `ln(1 + W / 1,000,000)`，再用本盘近期中位数、MAD 和 95 分位计算稳健 z；候选异常不写回基线，且需按采样间隔换算后连续覆盖约 5 秒，避免一次备份或编译任务污染参照。该标签只描述工作负载，不是寿命百分比。

固定文件读写探针默认关闭。启用后才会在目标文件夹创建带归属标记的 `.diskguard-probe`，用固定种子生成相同的 1 MB 内容块，按设定大小（32–512 MB）顺序写入并 `Flush(true)`，再顺序读回并以 FNV-1a 校验；写入 / 读取分别计时，完成、超时或异常都会清理自有文件。它不读取用户已有的大文件、不做随机写或全盘扫描，但是真实写入会产生对应写入量，计划可设为仅手动、每小时、每 6 小时、每天或每周；结果只适合同机、同路径、相近环境的趋势参考。

原生协议查询只读取控制器日志，不执行压力测试、自检、修复、重置或写入命令。长期模型的详细设计仍保存在上级目录的 `disk_guard_longterm`，当前 EXE 采用内存学习以保持便携和低写入；启动时性能计数器初始化可能耗时数秒。
